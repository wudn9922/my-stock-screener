# Public research datasets — research-v1

This extension retains Python → versioned static reports → React/TypeScript on the existing `/my-stock-screener/atlas/` Pages site. No database migrations, new credentials, paid APIs, notification defaults, order execution, chart overlays, or user-data migrations are introduced. The original price cache, universe, chart engine, authentication and LINE jobs remain authoritative.

## Contracts and provenance

`docs/report/research/` contains independently updated `institutions.json`, `volume.json`, `alerts.json`, `sec-radar.json`, `world-assets.json` and per-symbol `institutions/`, `volume/`, `sec/` files. A stock request loads only its small shard; global feeds load only when their disclosure opens. Files are written atomically. Missing data is `null`, never an invented zero. Expected remote/format failures preserve original observations and retrieval times, changing availability to `stale`/`unavailable`. Programming errors fail the job. Retained shards are never replaced by an empty fetch.

Every dataset carries source/sourceUrl, observation `asOf`, `fetchedAt`, `generatedAt`, nullable `publishedAt`, `status`, `missingReason`, and `methodVersion: research-v1`. HTTP Last-Modified is a file modification timestamp, retained separately in receipts/sourceLastModified, **not** a claimed publication timestamp. An unavailable official release time stays null. `asOf` is never relabelled to the collector's date. Per-event sources and filing acceptance timestamps are retained where provided. Numbers are finite JSON numbers, share counts are integers, percentages use 0–100 units, changes in ownership use **percentage points**. Python functions are the reproducible indicator implementation; the frontend only recomputes the four structure ratios/streaks when tool thresholds change. Raw daily inputs remain the repository's `data/*.csv` and `.cache/universe-full/bars/*.csv` (existing split-adjusted OHLC, dividend-unadjusted; volume adjustment not independently verified).

Large data is split by stock with 120 published institution sessions / 53 TDCC observations / 21 inspectable recent volume features / 400 calendar days of SEC and alert history. The institution snapshot includes all positive-day price inputs used in estimates. Changed datasets have separate commits; timestamp-only rewrites of unchanged stock shards are suppressed. The full-market cache remains an Actions cache, not a second quote service. Cache eviction rehydrates institution histories from published stock shards; dates absent from a public feed are not cached as zero.

## Calculations

* RVOL20 = current positive-volume completed daily bar / mean volume of the **previous** 20 positive-volume valid daily bars. Today is excluded. Fewer than 20 valid predecessors → null. Ordinary 5/20/60-day volume means and 5/20-day amount means **include** the latest completed session; every mean exposes its observation count.
* In each 5/10/20-session window, each directional denominator includes only valid daily returns with a known causal RVOL baseline. Up-shrink = up days with RVOL < shrink threshold / valid up days ×100; down-expand = down days with RVOL > expand threshold / valid down days ×100. Up-expand and down-shrink stay separate. Equality is neither shrink nor expand. Defaults are 1/1; abnormal-volume defaults independently use ≥2 / ≤0.5. No directional days → N/A. Small samples (<80% or fewer than 5 observations) are labelled low confidence. No composite score.
* Missing/zero-volume rows break directional streaks and are not silently treated as trading returns. Known corporate actions and >40% unconfirmed jumps conservatively invalidate a comparison and restart volume warmup. This does not claim all dividends/splits can be identified from OHLC alone; the price/volume adjustment limitation is displayed. Market session dates are taken from existing daily CSVs and current-day incomplete bars are excluded using Taipei/New York clocks.
* ADV = mean daily turnover in local currency. Official amount is preferred when supplied; otherwise close × shares is an explicit **turnover proxy**. Amihud20 = mean(abs(daily fractional return)/daily local-currency turnover) ×1,000,000, with daily frequency and per-million-local-currency units shown. High-low range = (high−low)/previous close ×100; it is not bid-ask spread. No cross-currency ranking is performed.
* Institutions 1/5/10/20/60 = sum of actually available official net shares over that many published market sessions. Missing rows reduce the observation count; incomplete windows never claim complete coverage. Consecutive net-buy/sell runs break at missing market-session rows. Taiwan lots = shares/1,000; stored data stays in shares.
* Large holders >400 lots = grades 12–15 shares / grade 17 inventory ×100; >1,000 lots = grade 15 shares / grade 17 inventory ×100. Counts sum the corresponding holder grades. Differences are percentage points. Week comparisons seek an actual calendar-week baseline within 3 days, never use a different missing week's array index. 52-week changes require 53 retained weekly observations. These are depository-account distributions, not precise ultimate-beneficiary consolidation or institutional transactions.
* Estimated positive-net-buy-day reference = Σ(market daily average × max(institution net shares,0)) / Σmax(net shares,0). Zero denominator → N/A. Market VWAP = official amount/shares when available; the existing price CSV currently usually needs the explicitly labelled **closing-price proxy**. Per-role 5/20/60-session outputs include close range, market-average/proxy range, matched days, positive days, coverage, current cached close/date and distance `(cached close/reference−1)×100`. This cannot identify actual holdings, remaining inventory, account owners, trade-level fills or a defended price. No per-stock official institutional monetary-fill data is claimed; aggregate market institution turnover cannot establish a stock's institutional cost.
* Asset changes = `(latest/baseline−1)×100`, baseline is latest actual observation at/before the calendar target. Maximum baseline lag: 7 days daily, 45 days monthly; no interpolation. Monthly 1d/1w is N/A. YTD uses the current year's previous-year-end baseline and is N/A when the latest observation is from an older year; month/year targets use calendar shifts, not fixed 30/365-day approximations. Monthly dates represent the observation month (first day), not publication on that day. Spot history can include negative observations without inventing a positive price.

## Run, backfill, resume and deployment verification

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/build_tw_chips.py --lookback-days 10
.venv/bin/python scripts/build_research.py institutional --days 95 --budget 600
.venv/bin/python scripts/build_research.py volume --cache .cache/universe-full
.venv/bin/python scripts/build_research.py alerts --days 95
.venv/bin/python scripts/build_sec_radar.py --budget 600 --days 95 --symbols AAPL,MSFT,NVDA
.venv/bin/python scripts/build_world_assets.py
.venv/bin/python -m unittest discover -s tests
cd atlas
npm ci
npm run typecheck && npm run lint && npm test && npm run build
VITE_PUBLIC_BASE=/my-stock-screener/atlas/ npm run build:pages
npx playwright install --with-deps chromium webkit
npm run test:site -- research-modules.spec.ts financials.spec.ts pe-river.spec.ts stock-volatility.spec.ts screener-filters.spec.ts unified-console.spec.ts
```

`Research public data` schedules five independent matrix jobs at UTC 00:23/08:23/14:23/20:23 weekdays, bounded to 18 minutes each and a 600-second collection budget. `fail-fast:false` keeps unrelated modules running. The volume job restores the existing full-market Actions cache; local absence of that cache yields explicitly partial coverage. The existing `tw-chips.yml` retains its original cadence and now also persists distribution history. Research jobs publish only their own report paths and use rebase/non-force push retries. Existing daily reporting, LINE and Supabase jobs are not reordered. `SEC_USER_AGENT` may be set as an Actions repository variable with the operator's genuine contact; the already configured repository contact is the default, no new secret needed.
