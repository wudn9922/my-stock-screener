# 股票均線參數一致性（2026-10-29）

## 問題與決策

原本圖表只讀本帳號的圖表指標，未讀 Supabase `stocks`。固定編輯器又只尋找並寫入 `group_id=ungrouped`，所以一檔原本有分組參數的股票可能新增第二筆無分組設定；Python 報告／監控及選股使用的優先順序也不同，編輯原筆後未必生效。

現在同帳號、同代號統一採用「原有分組股票列 → 無分組固定列 → 清單預設」。若歷史上有多筆分組，以最小 ID 的原筆為準，保留所有分組，不在背景遷移或刪除資料。裸台股代號與 `.TW` 對齊；`.TWO` 保留；美股 `BRK.B`／`BRK-B` 對齊。公開報告的掃描用通用 MA 不會變成訪客的個人固定參數。

共用解析器 `src/cloud/stockParameters.ts` 用於圖表、連續看圖、清單及選股；每日清單收集器沿用選股解析器。Python `fixed_parameter_map` 採用相同優先順序，供既有每日報告 loader 與突破監控讀取。無分組仍不構成報告／監控資格，沒有新增訊息或通知管道。

## 編輯與既有重複筆

- 編輯框先載入原有數值與分組；取消不寫入資料。「固定為個股參數」即使沒有建議均線檔也能編輯已保存的參數。
- 「改用目前圖表的均線」是另一個明確操作，確認前不取代原值。
- 確認後用原有 `stocks.save` 的 `id` 更新原筆，保留原代號與分組。控制台的新增表單若找到既有股票，改開原筆編輯框；由使用者決定是否更換參數／分組。
- 若同股票有無分組重複筆，畫面列出原值、重複值和清除說明。確認後先儲存原筆，成功才逐筆清除該股票的無分組重複筆。不刪其他分組或其他股票。
- 主要寫入失敗不刪資料；重複筆清除失敗顯示部分成功與重試說明。新優先順序仍以分組原筆為準。重試前重新載入；開始儲存前再次讀取原筆，發現資料已變更或新筆出現便拒絕覆寫。各次請求仍由原有 API 驗證雲端授權及本人所有權；帳號／授權切換時停止後續請求。
- 舊版設定匯入也按正規化代號查找既有股票，保留目前帳號版本並列出衝突；來源本身重複時先採原有分組，避免重新建立分組／無分組兩筆。
- 沒有任何原筆才建立無分組固定列。沒有改 Supabase schema、SQL、Edge Function 或登入機制。

## 圖表與連續看圖

- 開啟股票時讀取本帳號股票參數，補入日線 SMA，預設 2px。同週期同參數不重複。由此功能補入的指標有穩定 ID；原筆變更時更新這些指標。
- 保留手動指標、鎖定指標、其他週期、畫線、視窗及收藏設定。使用者可在本次查看中取消套用；不會在每次 React 更新時又強制加回。重新進入股票時恢復已保存參數。
- 參數讀取失敗顯示錯誤，不以建議均線覆寫資料。解析不完整／空參數不建立非法 SMA。
- 自選連續圖表使用個股已保存參數，否則用所選清單的均線。LINE 熱門無個股設定時保持無均線。只讀預覽不寫入任何股票或圖表設定。
- 初始及「重設」範圍為最後可用日 K 往前六個**日曆月**，月末做日期截短，假日以實際資料為準；全部歷史保留供長均線暖身及放大縮小。其他市場小圖原有 130 根預設不變；突破詳細小圖也用六個月。
- 自選頁只移除上方指數漲跌列。大盤／世界頁的指數、成交量及均線不變。
